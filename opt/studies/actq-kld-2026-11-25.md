# ACTQ input-quantization KLD calibration — 2026-11-25

## Summary

Teacher-forced full-vocabulary KLD was measured for EXL3 activation-input quantization on Inkling-2-Mini, using real English prompts of exactly 512 and 4,096 tokens and the following 256 real-text continuation tokens as forced targets. Perturbations were per-row int8 (`row8`), per-128-element-group int8 (`g128_8`), per-row int12 (`row12`), and additive deterministic Gaussian output noise at relative RMS ε spanning 1e-6 through 3e-2 (the exact points vary by context).

Headline ε values use the noise calibration curve. When the independent baseline-rerun control has nonzero mean KLD, that floor is subtracted before interpolation; raw table entries are unchanged. The primary curve is a log-log power-law fit over the four originally requested noise modes (ε = 1e-3, 3e-3, 1e-2, 3e-2). Supplemental lower-noise rows are shown as diagnostics but excluded from that primary extrapolation because they expose a finite-precision/discrete-response plateau rather than smooth scaling. Quantization rows are reported as operating points but are not pooled into the noise fit because input quantization error and additive output noise have different correlation structure.

| 512 | 0.000552319 | 6.04391e-06 | 0.5100 | 0 |

## Independent-run reproducibility control

- 512: the original baseline logits were deleted after the first batch, so no two-file rerun KLD control exists at this length. The replacement baseline used for supplemental low-noise analysis reproduced the original prompt-logit checksum exactly (`sum=-67886.47656`, first3 `[19.00048, 22.349546, 17.372496]`); the bitwise 4096 rerun control below validates runtime determinism.
- 4096: mean KLD 0, p99.9 0, top-1 agreement 1.0000, max logit Δ 0.

The control compares two complete unmodified runs started as independent processes with the same prompt and forced continuation. Exact zero means the runtime was bitwise reproducible for that measurement. A nonzero value is a measurement floor for the KLD comparison, not an ACTQ effect.

## Method

- Repository/branch: `t3/actq-kld-epsilon-study-3`.
- Model: `$HOME/models/inkling` (Inkling-2-Mini EXL3, GTX 1060 6 GB, sm_61).
- Prompts: exact-token real English text from the local `/usr/share/doc` corpus, generated with `crates/inkwell-tokenizer/examples/tokexact.rs`.
  - `/home/ash/actq-artifacts/p512.txt`: 512 tokens, 1,961 bytes.
  - `/home/ash/actq-artifacts/p4096.txt`: 4,096 tokens, 15,911 bytes.
  - `/home/ash/actq-artifacts/cont512.genids` sha256 `34fba32a14b6d6f1e09964d5f7f92c485bbab5a855346bda08a1f6d239b63e67`.
  - `/home/ash/actq-artifacts/cont4096.genids` sha256 `7bea23ace81136284c48a611b9ca86eec44fc08c07e690c6ff216ad7bfd708f3`.
- Teacher forcing: both baseline and perturbed runs fed the same fixed real continuation through `INKWELL_FORCE_IDS`; hidden-state histories are aligned token-for-token. Compared rows are the 256 continuation positions.
- Metrics: full softcap-corrected softmax rows as emitted by the runtime, fp64 analysis in `analyze_pair`; KLD direction is baseline || perturbed. p99.9 is a linear quantile over 256 rows, so it is a near-max tail statistic rather than a high-precision population estimate.
- Perplexity: mean NLL of the forced target token, exponentiated; delta is `(ppl_sim/ppl_base - 1) * 100%`.
- Quantization: `round-half-even` (`rintf`), scale max-abs/127 or /2047, clamp, applied in place after the input Hadamard and before the EXL3 GEMV. It covers dense attention projections, dense single projections including the EXL3 unembed, serial/cached MoE expert gate/up/down inputs, and the corresponding ntok paths.
- Noise: deterministic content-seeded Box-Muller Gaussian perturbations of complete GEMV output rows. Dense rows are perturbed after the orthogonal output-Hadamard epilogue because the fused kernel does not expose a complete pre-epilogue row; an orthogonal rotation preserves i.i.d. relative-RMS Gaussian noise in law. MoE rows are perturbed on the raw core-output buffer before the output Hadamard.
- CUDA graph execution remained enabled for measurement runs. Quantization/noise kernels are ordinary stream-ordered kernels and are captured with the rest of the graph.
- Default behavior check: sim OFF, standard ctx512 greedy run produced generated-text md5 `5cbe8e06`, peak 5,032 MiB.
- Early GPU runs used `nice -n 19 flock /tmp/inkwell-gpu.lock` with inherited locked fds for inner batch runs. After the queueing rule changed, new ultra-low-noise runs were launched as `gpu-run -p low -t <tag> -- <cmd...>`; `gpu-run` supplies the same nice level and lock. Peak per-run process VRAM stayed below the 5,080 MiB cap.

Representative measurement command (one process per mode; the batch iterated the mode list):

```
gpu-run -p low -t actq -- env GGML_PASCAL_GRAPHS=1 \

```

## Caveats

- The output unembed is an EXL3 matrix in this model and is included, matching the literal “every EXL3 matrix input” contract.
- Quantization ε values are pooled means over the specified dump layers/positions, not exhaustive measurements of every layer or of the unembed input.
- KLD tail statistics at 256 rows are noisy; means are the primary fit input.
- Noise realizations are deterministic but content-seeded, so noise streams downstream differ once upstream activations differ. This gives deterministic runs but not common-random-number coupling across ε values, which increases point-to-point scatter in the fit.
- Low-error response does not approach zero smoothly. At 4096 tokens, noise ε = 1e-6, 1e-5, 3e-5 and 1e-4 all have mean KLD between 0.00131 and 0.00343 despite exact baseline reproducibility; ε = 3e-6 is also affected. This is consistent with chaotic amplification of fp32 rounding and discrete expert-routing changes. Consequently the reported ε for mean KLD 1e-4 is a high-signal power-law extrapolation of the requested noise sweep, not a directly observed low-noise crossing. At 4096 it should be treated as especially uncertain.
- The original 512 baseline logits were deleted after the first batch. If a replacement 512 baseline is used for supplemental low-noise points, the report's baseline checksum comparison and independent-run control document that substitution.
